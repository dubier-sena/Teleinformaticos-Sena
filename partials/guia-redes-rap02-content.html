Bienvenida a la Guía

Del «saber teoría» al «dar soporte real»

▾

Cordial saludo, aprendiz. En la guía anterior aprendiste a identificar tipos de redes, topologías, medios de transmisión y el esquema de direccionamiento IP. Ahora verificarás que una red funciona correctamente: esa es la diferencia entre un técnico que sabe teoría y uno que puede dar soporte real en una MiPyme de Boyacá.

Imagina que la señora Carmen —la dueña de la papelería— llama porque «el computador no puede imprimir en red» y «la cámara de seguridad no aparece». El técnico no puede abrir el computador ni cambiar cables al azar: necesita un método. Ese método es precisamente lo que desarrollarás en esta guía.

Equipo con Windows 10/11, acceso a CMD, conexión a internet y Cisco Packet Tracer (Switch 2960 y Router 4321). Toma captura de pantalla de cada prueba: sin evidencia, no hay evaluación.

Comandos de diagnóstico y procedimiento de averías

2 actividades · práctica CLI + presentación técnica

▾
3.3.1Comandos de diagnóstico CLI — exploración y práctica▾

Los comandos son la herramienta principal de un técnico de redes. Ejecuta cada comando en CMD (Windows + R → escribe cmd → Enter), toma captura y registra el resultado.

1
ipconfig /all

Muestra IP, máscara, gateway, DNS y MAC del equipo.

2
ping 127.0.0.1

Loopback: verifica que la tarjeta de red del propio equipo funciona.

3
ping [IP del gateway]

Verifica la comunicación con el router. Si falla: problema en la LAN. (reemplaza con la IP de tu gateway)

4
ping 8.8.8.8

Conectividad a internet por IP. Si falla pero el gateway responde: router/ISP.

5
ping google.com

Verifica DNS además de internet. Si 8.8.8.8 responde pero el nombre no: falla el DNS.

6
tracert 8.8.8.8

Muestra la ruta de saltos hasta el destino. Útil para localizar dónde se corta la conexión.

7
nslookup google.com

Consulta el servidor DNS para resolver un nombre a una IP.

8
netstat -n

Muestra las conexiones de red activas con IPs y puertos.

✅ Respuestas guardadas correctamente.
3.3.2Procedimiento de diagnóstico de averías — presentación técnica▾

Un técnico profesional no prueba comandos al azar: sigue un método. Elabora una presentación (PowerPoint, Canva o Google Slides, mínimo 15 diapositivas) aplicando el procedimiento estructurado.

📝 Procedimiento de resolución de averías

1) Identificar el problema · 2) Establecer teoría de causa probable · 3) Comprobar la teoría · 4) Establecer plan de acción · 5) Implementar la solución (o escalar) · 6) Verificar el funcionamiento completo · 7) Documentar.

⚙ Parte 1 — Configuración básica (requisito para las pruebas)

Sigue cada paso en orden. No avances al siguiente hasta confirmar que el actual funciona.

  1. 🔌 Construye la topología en Packet Tracer
    • Agrega: Router 4321 (R1), Switch 2960 (S1), Switch 2960 (S2), 4 PCs en Planta 1, 4 PCs en Planta 2.
    • Conecta cada PC a su switch con cable recto.
    • Conecta S1 → R1 Gi0/0/0 y S2 → R1 Gi0/0/1 con cable Gigabit recto.
  2. ✎ Aplica configuración básica en R1, S1 y S2
    • Hostname: R1-XXX / S1-XXX / S2-XXX (XXX = últimos 3 dígitos de tu identidad).
    • Banner de bienvenida (banner motd), enable secret, contraseñas de consola y VTY.
    • service password-encryption, no ip domain-lookup, logging synchronous.
    • Guarda con write memory en cada dispositivo. (Ver cápsula 📌 si no recuerdas los comandos.)
  3. 🌐 Configura las interfaces del router R1
    • Gi0/0/0 → 192.168.1.1 /24 (no shutdown) — gateway Planta 1.
    • Gi0/0/1 → 192.168.2.1 /24 (no shutdown) — gateway Planta 2.
    • Verifica: show ip interface brief — ambas deben aparecer up/up. (Ver cápsula 📌.)
  4. 🔀 Configura la IP de administración VLAN 1 en S1 y S2
    • S1: interface vlan 1 → 192.168.1.2 /24 + ip default-gateway 192.168.1.1
    • S2: interface vlan 1 → 192.168.2.2 /24 + ip default-gateway 192.168.2.1
  5. 💻 Asigna IPs estáticas a los 8 PCs (según tabla de direccionamiento de arriba)

    • Desde PC0: ping 192.168.1.1 → debe responder (gateway Planta 1).
    • Desde PC4: ping 192.168.2.1 → debe responder (gateway Planta 2).
    • Si falla, revisa no shutdown en las interfaces y que la IP del PC tenga el gateway correcto.

  4. En cada Laptop: retira la tarjeta de red cableada (si tiene) e instala la tarjeta WPC300N

  6. Verifica con ipconfig que recibió IP en el rango 192.168.20.100–150
🏠 Parte 2 — DHCP en el router (Bloque C)

Configura un pool DHCP en R1 para los dispositivos inalámbricos:

ip dhcp pool VISITANTES
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.1

ip dhcp excluded-address 192.168.20.1 192.168.20.99

Verifica con show ip dhcp binding que la Laptop recibió IP del rango .100–.150.

🌍 Parte 4 — NAT overload (PAT) hacia internet (Bloque D)

Configura NAT en R1 para que toda la LAN salga con la IP pública 200.15.10.1:

access-list 1 permit 192.168.20.0 0.0.0.255
ip nat inside source list 1 interface Gi0/0/1 overload
interface Gi0/0/0
 ip nat inside
interface Gi0/0/1
 ip nat outside

Verifica con show ip nat translations después de hacer ping al ISP desde un PC.

Glosario de términos
📖

Glosario

Términos clave de la guía

▾
Router
Interconecta dos o más redes y reenvía paquetes IP; en MiPymes actúa como puerta de enlace y puede hacer NAT.
Switch
Dispositivo de capa 2 que conmuta tramas Ethernet entre puertos dentro de una LAN.
Access Point (AP)
Brinda acceso inalámbrico (Wi-Fi) a una red cableada.
TCP/IP
Conjunto de protocolos base de Internet organizado por capas; IP direcciona y encamina, TCP/UDP transportan datos.
DHCP
Asigna automáticamente IP, máscara, gateway y DNS a los equipos cliente.
DNS
Traduce nombres de dominio (p. ej. www.google.com) a direcciones IP.
NAT
Traduce direcciones IP privadas a una o varias públicas para salir a Internet desde una LAN.
ICMP
Protocolo de control y diagnóstico; el comando ping lo usa para verificar conectividad.
Gateway (Puerta de enlace)
IP del router por donde un equipo envía el tráfico hacia otras redes.
Máscara de subred
Define qué parte de la IP es red y qué parte es host.
APIPA (169.254.x.x)
IP link-local automática cuando el equipo no obtiene configuración válida de DHCP.
VLAN
Segmentación lógica de una LAN en dominios de broadcast independientes.
tracert / traceroute
Muestra la ruta (saltos) hasta un destino; útil para ubicar dónde se pierde la conexión.
nslookup
Consulta servidores DNS para verificar la resolución de nombres.
netstat
Muestra conexiones de red activas, puertos en escucha y estadísticas.
Cisco Packet Tracer
Simulador de redes para construir topologías, configurar dispositivos y validar conectividad.
Telnet
Acceso remoto por texto plano (sin cifrado); útil en laboratorio, no recomendado en producción.
Firewall
Filtra el tráfico de red según reglas para permitir o bloquear comunicaciones.
